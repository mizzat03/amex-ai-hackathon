# Responsible-AI and security boundary

- Deterministic code owns metrics, incident lifecycle, affected scope, hypothesis ranking and
  evidence tier. The model cannot overwrite these results.
- Every material incident claim needs an allowlisted evidence citation; procedural guidance needs
  an approved versioned runbook citation. Numerical claims resolve to exact structured fields.
- Evidence, runbooks, tool results and user messages are untrusted data. Prompt-like content cannot
  grant tools, cross incident boundaries or change policy.
- The only tools are bounded incident-scoped Python reads. Duplicate, cross-incident, oversized,
  unknown and write-shaped calls are rejected outside the model.
- No unvalidated model text is streamed or displayed. Invalid schema, fabricated citations or
  numbers, causal confidence, cross-incident leakage and claimed execution are hard failures.
- Recommendations remain risk-labelled, cited and human-controlled. The product executes no
  remediation and fixes review attribution to the server-side `demo-operator`.
- Interaction audits contain versioned configuration, context/tool counts, provider metadata,
  usage when supplied, validation results and final status—but no credentials or hidden reasoning.
- Usefulness feedback is stored for offline review only. It neither trains a model automatically
  nor changes deterministic RCA.
- Synthetic inputs exclude PAN, CVV/CVC, PIN and real customer/merchant identity. A production
  deployment would additionally require enterprise identity, authorization, data minimisation,
  retention, provider-contract and compliance review.
